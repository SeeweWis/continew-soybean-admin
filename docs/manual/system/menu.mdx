菜单管理维护系统的导航结构与权限标识，功能入口在「系统管理 -> 菜单管理」，后端接口前缀为 `/system/menu`，对应 `MenuController`。菜单数据存储在 `sys_menu` 表，同时承担「路由配置」与「权限资源」两个职责。

## 菜单类型

菜单类型由 `type` 字段区分，取值来自 `MenuTypeEnum`。

| 类型 | 值 | 用途 |
|:-----|:---|:-----|
| 目录 | 1 | 一级分组，只负责组织与展示，不指向页面 |
| 菜单 | 2 | 具体页面，配置路由地址与组件路径，参与动态路由生成 |
| 按钮 | 3 | 页面内操作点，只配置权限标识，用于按钮级鉴权 |

## 菜单字段

`sys_menu` 表的主要字段如下。

| 字段 | 说明 |
|:-----|:-----|
| `title` | 标题，同一上级下唯一（`uk_title_parent_id` 联合唯一索引） |
| `parent_id` | 上级菜单 ID，根节点为 0 |
| `type` | 类型（1：目录；2：菜单；3：按钮） |
| `client_type` | 终端类型（取值于字典 client_type：PC 桌面端；XCX 小程序；ANDROID 安卓），默认 PC |
| `path` | 路由地址；外链菜单填完整 URL（http/https 开头） |
| `name` | 组件名称，对应前端路由 name，用于页面缓存（keep-alive）匹配 |
| `component` | 组件路径，对应前端 `src/views` 下的 `.vue` 文件 |
| `redirect` | 重定向地址 |
| `icon` | 图标 |
| `is_external` | 是否外链 |
| `is_cache` | 是否缓存，开启后页面切换页签时不重新渲染 |
| `is_hidden` | 是否隐藏，隐藏后不出现在侧边栏，但路由仍可访问 |
| `permission` | 权限标识，如 `system:user:create` |
| `sort` | 排序，默认 999 |
| `status` | 状态（1：启用；2：禁用） |

## 路由地址与组件路径的填写规则

`MenuController.preHandle` 在新增、修改时统一修正参数。

- 勾选「是否外链」时，`path` 必须以 `http://` 或 `https://` 开头，否则报「路由地址格式不正确」；
- 非外链时，`path` 不允许是完整 URL，保存时自动补前导 `/`；`name` 与 `component` 自动去除前导 `/`。

前端登录后调用 `/auth/user/route` 拉取当前用户可见的菜单树，按 `component` 经 `import.meta.glob('@/views/**/*.vue')` 匹配组件并注册动态路由。`component` 填相对 `src/views` 的路径（不带前导 `/`、不带扩展名），例如 `system/user/index`。

## 终端类型

`client_type` 字段区分菜单归属的终端，取值与 `sys_client.client_type` 及字典 `client_type` 一致（PC、XCX、ANDROID）。菜单管理页顶部的终端 Tab 按此过滤列表；新增或修改目录、菜单时可选择终端类型，按钮类型不单独配置，保存时自动继承上级菜单。

`/auth/user/route` 按当前令牌所属客户端的 `client_type` 过滤后返回：桌面端客户端登录只返回 PC 菜单，小程序客户端（`refresh_token_mode = BODY`）登录只返回 XCX 菜单。小程序工作台展示的菜单名称、图标、排序均来自此处配置。

## 小程序基础菜单

初始化脚本为 `mini_program_user` 角色预置 XCX 终端的「基础服务」目录及其「个人中心」「消息中心」菜单，并在「业务应用 → 审批中心」下预置「我的申请」「我的待办」菜单。两项审批菜单分别打开小程序的申请列表和待办列表，当前列表页仅提供浏览。默认角色只获得列表按钮；详情、新建、撤销、同意、拒绝、转办按钮已预置供管理员按需授权，对应的小程序操作界面需在业务流程接入时实现。

XCX 路由要求同时授权菜单节点和其下至少一个按钮节点；只授权菜单或只授权按钮都不显示该菜单。目录仅在存在可见菜单时显示。因此「业务应用 → 附件上传」是可勾选的按钮权限，不会生成小程序菜单；只勾选它也不会显示空的「业务应用」目录。个人中心和消息中心的「进入」按钮只控制动态菜单入口，两个接口仍按当前登录用户限定数据范围，不以该按钮作为后端接口鉴权。固定 TabBar 入口不受动态菜单显示规则影响。

个人资料和个人消息接口使用当前登录用户身份，不需要额外的按钮权限。头像更新使用 `PATCH /user/profile/avatar`，无需授予文件管理权限。业务附件调用 `POST /system/file/upload`，使用「附件上传」按钮对应的 `system:file:upload`；该权限也涵盖文件上传配置和分片上传接口，不应与头像能力混用。

迁移会撤销 `mini_program_user` 角色旧的桌面端上传授权，并由小程序「附件上传」按钮接管。其他角色可能仍通过桌面端「文件管理 → 上传」授予相同权限；用户权限取全部角色的并集，撤销附件上传时需检查重复授权。部署后清除角色菜单缓存并重新登录，才能更新已登录用户的菜单与权限。

## 权限标识与按钮鉴权

按钮类型（`type = 3`）的 `permission` 字段是后端接口鉴权的依据。CRUD 类接口由 `BaseController.preHandle` 按「模块：资源：动作」自动生成权限码，例如 `POST /system/user` 要求 `system:user:create`。前端按钮用 `v-permission="['system:user:create']"` 指令控制显隐，无权限时不渲染。

<Callout type="info">
新增业务模块时，代码生成器会同时产出菜单 SQL（含按钮权限标识），在菜单管理中执行或手工录入后即可挂到角色上。按钮权限标识建议与后端权限码保持一致，避免前后端两张皮。
</Callout>

## 清除缓存

角色-菜单关联结果缓存在 Redis（键前缀见 `CacheConstants.ROLE_MENU_KEY_PREFIX`）。菜单或角色调整未即时生效时，可点击「清除缓存」（`DELETE /system/menu/cache`，权限码 `system:menu:clearCache`）按前缀批量删除缓存键，下次请求重新加载。
